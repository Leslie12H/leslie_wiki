# 登录验证码测试通道评审

**Why** — 自动化复用业务登录流程时，验证码的交付对象从号码或邮箱的控制者变成测试人员或执行器。账号归属、发码分流和业务会话的生命周期因此都需要显式定义。

**How to apply** — 先确认测试环境和身份隔离，再按以下场景验收。

- **多业务接入**。共享登录服务按项目和渠道默认关闭、逐项启用。统一接入契约声明标识格式、账号租用、取码授权和关停信号，接入业务自行维护其本地会话。验收覆盖两个独立项目、启用与关闭两种状态，以及跨项目取码被拒绝。
- **身份与发码分流**。测试身份使用预留命名空间，归一化后在服务端按环境和项目判定。对未登记、回收和查询异常的测试标识，断言供应商发送次数为零。验证并发首次登录时，测试主体与既有普通用户的身份始终独立。测试邮箱可采用 .test 保留域。[RFC 2606 §2](https://www.rfc-editor.org/rfc/rfc2606.html#section-2)
- **取码权限与存储**。区分管理测试账号和读取验证码的权限。执行器按运行绑定测试账号，取码审计保留操作者、账号和结果，脱敏调试输出。验证码校验值由数据库以外的密钥保护，可逆副本仅保留至允许取码的时限。
- **并发与重试**。若业务契约只接受每个账号的最新码，每个并发执行使用独立账号租约。验收同一验证码只消费一次、重发仍受账号级失败限额，以及上游已消费但下游建会话失败时的恢复。[NIST SP 800-63B-4 §3.1.3](https://pages.nist.gov/800-63-4/sp800-63b.html#out-of-band)
- **结束状态**。分别验证到期、回收和关停对未消费验证码、刷新凭据、已签发访问令牌及业务本地会话的影响。发布验收记录各层的失效时限。真实传输用例单独核对供应商的送达与失败处理。
