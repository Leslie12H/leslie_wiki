# 知识库多分支历史分叉的同步

**Why:** 多个会话从不同基线补写同一知识库，会让本地主工作目录与远端 main 各自累积独立提交。另开临时分支发布单篇记录不能自动更新主工作目录；长期只报告推送拒绝，会留下未跟踪正文和两边独有的历史。整份选择 ours/theirs 会丢失另一边的后续核验。

**How to apply:** 用户授权完整同步时，先 fetch 并固定双方 SHA，备份全部 Git refs 与未跟踪文件；检查其他分支及可用工作树是否还有遗漏。审阅并提交知识库内未跟踪正文后，普通 merge 远端 main，保留双方提交祖先关系。逐页辨别纠正旧结论与追加新证据：较早的状态应标明日期，后续修复及验收记录保留，不能用旧“未实施”覆盖新证据。目录保留双方链接，日志按追加方式补入远端独有记录。

提交前检查双方文件集合、未跟踪文件哈希、目录目标、双方日志记录、相对链接、frontmatter 和冲突标记。推送使用普通快进；若远端再次前进，重新读取并合并新提交，不强推。推送后独立读取远端 main，确认与本地 HEAD 一致且工作目录干净。
