# 发压器存在、调度达标与生产就绪分开验收

**Why:** 复用 Kubernetes 资源不必购买机器，但 Pod Running 不能证明调度、图片传输、持久化记账或公网吞吐合格。2026-11-14 的回环自检发现逐请求 fsync 与相对 sleep 都能使实际请求率明显低于配置目标；也遇到选定节点不能挂载某 NAS、不能拉取公共镜像、静态前端镜像不包含 Node 的部署差异。

**How to apply:** 先查看历史执行报告，再核对现有节点余量与实际镜像/存储能力；用独立限额 Pod 和专用持久目录，显式覆盖待命命令。用真实图片、真实 HTTP 回环、实际磁盘同步检测发压端；同批持久化同步必须仍保证请求意图先落盘，时钟采用固定时间点，过期请求不集中补发。按实际发送/漏发与服务端观测分别判断，不能把回环吞吐当作生产或公网容量。

逐窗口漏发与全程平均发送率分别验收；短测通过不能覆盖后续持久化尾延迟。优化查询台账时保留每次请求意图/回执，通过组织、任务和原始序号关联完整输入，状态不变无需重复整份输入。批量 fsync 的等待仍须在请求发送前完成，记录同步尾延迟定位发压端瓶颈，不放宽漏发门槛来制造通过。

持续写 NAS 台账会增加文件缓存，cgroup `memory.current` 接近 limit 不等于进程工作集同样饱和。保留总量并用 `memory.current - inactive_file` 展示工作集，依据 [cAdvisor 计算](https://github.com/google/cadvisor/blob/8164b38067246b36c773204f154604e2a1c962dc/container/libcontainer/handler.go#L835-L844)。未知或不一致采样不补成健康；工作集指标也不是 OOM 风险的完整证明。

容量、持久化同步延迟和资源创建权限分别验收。NAS `df` 展示的逻辑容量不证明独占配额或同步写入延迟；没有 Available PV 也不证明整个云账号没有空闲云盘。云盘最低容量与性能级别有关，沿当时官方规格核对，不把某一等级下限推广到全部云盘。`kubectl auth can-i create pvc/pod` 不证明能够创建 StorageClass，更不证明 CSI 云角色有 CreateDisk/AttachDisk 权限、账户额度或已获新增费用授权；不得用付费创建试探权限。具体占用、权限核验、候选规格、保留时长与报价边界见工作区 `docs/magi2-essd-candidate-plan-20261114.md`。

不能把发压器自设的毫秒级调度容差当作业务 SLA，再据其失败直接要求购买存储。先检查日志持久化是否处于发送关键路径、只读 GET 是否被不必要的发送前同步阻塞、控制/指标写入是否阻塞主调度循环。短距离预写 POST 意图与后台批写 GET 证据是待验证的解耦方向，仍须保留有界队列、查询预算恢复、未知 POST 不重发和人工停机。发压质量用短窗突刺、分钟实发偏差与连续窗口判断；业务安全保护单独处理。新标准必须先冻结再复测，原失败报告不可改判。2026-11-14 的具体评审与实施状态沿工作区 `docs/magi2-runner-pacing-review-20261114.md` 核对。

## 证据入口

- 历史 Dev 执行位置和共享资源边界：工作区 `docs/dev-multitenant-load-report-20261028.md`。
- 当前两区接线、配额、素材、真实遥测、阻塞和正式步骤：工作区 `docs/production-load-final-readiness-20261114.md`；早期待命部署记录在 `docs/magi2-runner-readiness-20261114.md`。实时位置和状态沿本次独立回读，不在知识库固化实例、Pod、版本或测试计数。
- 人工启动/暂停/继续/停止、持久化命令回执、断开终端与 Pod 故障后的区别：`postman/load/magi2/deploy/README.md`、`control.mjs`、`launch.mjs`。
- 成功延迟窗口与样本门槛：`latency-gate.mjs`、区域配置与相应 tests；失败/超时不得混入成功分位数，查询成功不代表生成成功。低流量 P99 基线和统计充分性须明确标识。
- 缺真实遥测、身份、准入、素材映射或输入契约时阻止生产启动；模板填 true、旧看板有序列或本地测试通过不构成生产验收。停新增后保留原台账和只读续查，不自动重放 POST。


## 2026-11-14 人工逐档与预写解耦

**Why:** 固定预设阶梯不能代表用户每次明确授权的 QPS 和时长。把短档样本不足当作已达容量、把档位结束当作存量任务完成，或在新档扩大查询预算后丢失其恢复上限，都会让控制与实际副作用脱节。高频普通观测的逐条完成回调和最终单条复制全部任务也会使发压器自身成为瓶颈。

**How to apply:** 每次只接纳一档明确 QPS 与时长，授权先持久化；到期停新增、保留查询并等待下一指令。暂停继续只影响当前档剩余时间，stop 或安全停止不能被新档绕过。短档缺样本保持未取得资格，不伪造通过；实际窗口偏差与业务保护继续独立停止。恢复仅恢复合法查询权限和预算，不恢复新增 POST。普通日志采用有界入队与后台批写，最终台账保存紧凑摘要，完整任务报告另存；关闭台账成功后才发布完整结果。

本次实现、人工 1 QPS 五分钟到 5 QPS 十分钟的控制验证、NAS 延迟注入和保留的失败原件，沿工作区 `docs/magi2-runner-pacing-implementation-20261114.md` 与 `postman/load/magi2/README.md` 回查。窗口、版本、计数和生产阻塞属于可变状态，不复制到知识库。回环只证明发压器行为，不证明生产两种协议均已部署可用或账务、素材清理已闭环。

## 2026-11-14 镜像、代码包与执行配置分别核对

**Why:** Pod 的运行镜像、已安装代码包和私有执行配置是三层独立状态。候选代码已经安装，并不代表正式入口已经采用人工分档或双协议配置。切换目标模型时继续沿用旧模型的准入和契约验证标志，会把历史成功误当作新模型可用；管理后台白名单成员关系也不能证明实际推理和图片输入契约通过。

**How to apply:** 先只读核对 Pod 镜像与待命进程、实际代码文件指纹、正式入口读取的配置，再决定是否更新；代码无需变化时只补齐配置。保留不可变版本和更新前配置，不覆盖历史候选或验证结果。配置合并保留现有组织、凭据引用、素材归属、遥测与保护字段；换模型后分别重新核对模型准入和两套接口契约，缺少新模型证据时不得继承旧 `modelAccessVerified`、`generationContractVerified` 等通过标志。更新前比较已审阅哈希，更新后独立读回并只读校验；安装和配置更新不调用启动入口，也不以通过静态校验宣称生产就绪。

上海配置补齐的实际版本、差异、只读验证与剩余阻塞沿工作区 `docs/magi2-runner-pacing-implementation-20261114.md` 回查，不在知识库固化当前部署状态。

## 2026-11-14 临时遥测源与Pod重建

**Why:** 挂在业务Pod里的临时遥测源不会随滚动发布自动迁移，旧Pod地址也可能被其他角色复用。只看配置仍有地址、输出文件时间新鲜或空快照为零，会把源失联、读错实例与缺样本误当作健康；刷新文件不能补回真实观测。

**How to apply:** 重接前核对当前角色、实际副本、Pod身份和目标运行Jar指纹，确认业务聚合方法仍匹配部署。将来源绑定到已核验的实例，沿真实HTTP请求与响应验证覆盖和错误，保留完整时间窗口；数据源失败、无有效观测或窗口不足保持未知或阻止启动，不写健康占位值。临时源的有效期、退出条件与过期后的行为须可核验；角色变化、IP复用或Pod重建后重新核对，不能仅替换地址或沿用旧成功标志。

上海重接的部署、临时源有效期、HTTP窗口、回执与实时就绪状态，统一沿API工作区 `docs/shanghai-telemetry-reconnect-20261114.md` 回查；知识库不固化临时地址、Token、运行计数或当前健康快照。
