# 对话调优需要按动作证明而非固定步骤放行

## 2026-10-22 候选准备由执行协议决定

当前实现、已接纳回执、性能与真实评分边界沿 Maxwell `output/evolve-unified-20261019/flexibility-acceptance-20261022.md` 核对；源码入口为 commands/optimization_verification、candidate_validation 与 Studio PreparedRunCardStore。不保存临时 Run 身份或通过结论。

**Why:** 候选存在不表示它必须经过平台外部资源 Provider；自包含 A2A Runner 在 Adapter 内物化，而资源协议候选依赖 Provider。前端按候选存在强制准备，会让合法 Runner 被错误的可信绑定要求拦截。首次计划按协议规范标志后，已接纳回执恢复又必须保留原选择，否则同键请求摘要会冲突。

**How to apply:** 新计划先按原业务、Work、可见性与精确 Variant 哈希读取冻结执行协议，在计算计划摘要前规范准备标志；只读准备不调用外部 Provider 或模型。正式提交继续执行原资源应用与预算准入。已接纳同键恢复按精确身份和原 preparedRef 还原，不重新解释旧请求或放松摘要校验；覆盖首次、接受后重开、错误作用域及两种协议的相邻路径。共享 Agent 不因验收而增加外部绑定。

## 2026-10-22 可编辑评分配置与执行编译边界

实际自然对话、校验修复和入库/评分结果沿同一验收记录查证；源码入口为 measurement.ValidateLLMConfig、methods 注册表和 commands 的 Case/草稿/新 Run 消费点。

**Why:** 模型即使阅读到真实方法描述，仍可能把旧 Judge spec 的字段填进新的逐题原生方法配置；草稿保存成功不证明评分可执行。若只在付费 Trial 后编译，用户会到运行阶段才发现这一错误；反过来要求所有草稿立即可执行又会阻止正常编辑。

**How to apply:** 草稿保持可编辑，在确认、物化和新执行消费点复用实际方法的纯编译校验，保留已接受精确回执优先恢复；未知、版本化和外部 opaque 方法继续遵从自身契约。方法资产按授权精确引用读取，缓存有界且在预算锁外，不为校验调用模型。把错误反馈交给 Agent 修订，再用干净自然会话验证真实可保存产物，不能把技术测试或说明稿算作自然场景成功。

## 2026-10-22 嵌套观察组件与已授权显式执行

源码和页面复现入口为 PreparedRunCard、PreparedRunCardStore 及 agent-resources 的调优 Prompt/optimization-strategy；当前发布、实际调用与提分状态沿验收记录核对。

**Why:** 命名函数内部与 observer 导出同名时，递归 JSX 可能解析为未观察的原函数，异步状态虽更新，嵌套审核却不出现。通用说明若仍声称每个 Run 都必须再次人类确认，也会把已由服务端验证的 Work-bound Grant 误述为不可用，制造额外流程卡点。

**How to apply:** 递归渲染引用被观察的导出组件，并用真实可观察状态更新测试嵌套对话。对已尝试提交但响应未知的动作，仅按同业务、Work、key 和请求摘要恢复已有回执，避免新键重派。首次授权及独立隐藏验收保留人类审核；已有匹配 Grant 的显式动作按现有服务端范围执行，不因自动编排阻塞重复索要许可。源文件、隔离 Preset 持久回读和新会话实际生效分别取证。

## 2026-10-22 可读资产目录不等于任务事件历史

当前源码与真实页面回读沿 Maxwell `output/evolve-unified-20261019/flexibility-acceptance-20261022.md` 查证；定位入口为 EVOLVE postgres 的 `ListArtifactsByAccess`、Studio 的 `loadSelectedAssets` 与 Ledger 的 `buildArtifactEntries`。本节不保存业务身份、临时事实数量或验收通过结论。

**Why:** 业务内独立配置原件可以出现在某个 Work 的可读资产目录中，供引用和编辑；可读不证明该 Work 创建、冻结或采用了这些原件。若把整个目录按原冻结时间直接混入任务对话，新任务会显示旧资源的系统事实；这类投影错误与会话串线或越权读取需分别取证。历史导入或采用的合法原件也可能早于 Work 创建，不能靠时间截断修复。

**How to apply:** 保留原件目录、引用入口及既有读取授权，只在任务时间线按精确 Work 归属投影。原件成员关系不代表采用事件：保留其真实冻结时间与哈希，使用中性的正式资产说明，不捏造“本任务冻结/采用成功”或当前时间。当前任务的草稿确认、候选和运行记录继续按自身真实事件展示，可从完整目录解析精确原件回执。回归同时覆盖独立资源排除、其它 Work 排除、历史成员原件保留、当前草稿引用独立原件以及切换任务首帧；实际页面与真实评分仍分别核验。

## 2026-10-22 自动调优阻塞与有效授权不能混为一谈

源码与真实出分状态沿 Maxwell `output/evolve-unified-20261019/flexibility-acceptance-20261022.md` 核对；实现入口为 EVOLVE domain/optimizationcontrol 与 postgres/optimization_budget 的公共 `consume`，并联查普通候选、显式运行和证据入账调用方。本节记录已确认的职责边界，不代表本轮修复、真实评分或发布已完成。

**Why:** 自动调优进入 `blocked` 只表示当前自动编排无法继续，不等于用户撤销了仍有效的 Grant。若公共预算账本直接按自动阶段拒绝所有入账，显式授权且合法的候选、运行或已取得证据也会被一并封死；只在上层放开按钮无法修复底层拒绝。

**How to apply:** 自动调度的阶段检查放在自动推进职责内；公共记账和显式动作按本次真实授权、权限、目标与资源范围、同根用量、幂等及必要时的短事务证明核验。自动阻塞不应要求新建任务、伪造阶段或重置计数才能继续；它也不是放宽授权、期限或范围的理由。复查所有共用 `consume` 的入口，用自动继续拒绝、显式合法动作可达、越权与额度不足仍拒绝、旧回执免费恢复的相邻回归分开证明；真实评分、比较与提分继续沿验收原件核对。

## 2026-10-22 Skill 源码更新只发送变动文件

当前源码与实际更新证据沿同一 Maxwell 验收记录查证；代码入口为 Studio pages/skills 的 SkillEditModal、SkillFileWorkspace 与 utils，复用既有 Skill 文件 patch。知识库不保存环境文件正文、凭据或临时业务身份。

**Why:** 为替换脚本或运行 ZIP 而重新上传完整 Skill 包，会把未变化的环境凭据带进源码更新通道，扩大读取、传输及误覆盖范围；只支持文本编辑又无法更新二进制依赖。首次安装所需的完整目录，与已有 Skill 的增量更新是不同动作。

**How to apply:** 已加载文件初始标记未改，保存时仅发送 dirty 文件的既有 `put`/删除补丁，未变动环境文件保持省略；替换二进制及原始文本字节复用 `contentBase64`，手动修改文本后再按新文本序列化。只更新既有路径并防止异步读取结果落到已切换的草稿。先审查实际待发送路径与文件类型，再验证保存回读及运行依赖；不得为了源码更新打包或重传凭据。首次安装仍须验证获准包的脚本、资源和配置目录完整，不能把增量更新规则误作允许缺依赖。

## 2026-10-22 来源快照与本次运行配置不能混作同一门禁

真实复现、源码修复及实际出分边界沿 Maxwell `output/evolve-unified-20261019/flexibility-acceptance-20261022.md` 核对；代码入口为 nextplay_runtime/runner、resource_manifest、materializer 以及 EVOLVE execution/runner_result、runner_applied。连接声明的关联修复沿 commands/executors 与 executor_declaration_patch_test 核对；不保存临时配置、凭据或发布结论。

**Why:** 历史来源只冻结部分 Prompt/Skill 原件时，不足以声称保留了完整旧 Preset；每条用例重新捕获活体 Preset 后再要求等于旧整体快照，会使正常新增工具等变化阻止执行。仅放宽 SDK 而不修平台回执等值要求，还会在结果回收再次拒绝。连接更新若在应用显式新声明之后清空旧 Card，也会把同次请求携带的新能力声明误删；健康探测未必能重建平台专用声明。

**How to apply:** 分开保存历史来源、本次实际隔离配置和逐项原件应用证明；复用当前已授权执行配置构建隔离实例，实际回读请求的资源与配置，记录真实 snapshot，不能把新身份伪装成旧快照。当前捕获与服务端复制之间的短期竞态校验仍负责防串配置，不应扩成跨 Run 的永久等值要求。历史结果比较依题集与评分口径，不强制重新构建任务或让 Agent 按固定顺序执行。更新连接先清旧连接状态，再应用本次显式声明；未提供声明时不跨连接继承旧能力。已确认远端终态的错误保留原失败，不再重复取消；取消状态核对避免附带大输入历史。技术回归通过后仍须真实执行、采集、评分和比较，不把接纳或结束当作质量验证。

## 2026-10-22 长任务等待、工具目录与当前状态的证据

具体代码、自然失败、真实异步回流和未完成的质量验收，沿 Maxwell `output/evolve-unified-20261019/flexibility-acceptance-20261022.md` 查证；SDK 入口为 nextplay_runtime 的 cli/runner/supervision，平台入口为 MCP provider refresh 与 Studio threads/traceModel。不保存临时 Preset、线程、模型额度或发布结论。

**Why:** 外层 Agent 定时轮询长任务会持续消耗模型调用次数，内层尚未结束时外层即可耗尽；脱离父执行的进程又可能继续占用远端资源。服务进程加载新工具说明不等于模型使用了新目录，持久 MCP 工具快照可能仍旧。完成后的历史 async interrupt 也不等于当前 Run 仍在等待。

**How to apply:** 复用宿主托管异步执行承接长等待，并在同一次有界等待中监督实际任务；按精确任务身份、原请求和进程出生标记处理恢复、截止和 owner 消失，不能依赖本机互斥锁证明跨节点唯一。比较模型实际请求中的工具说明与当前服务目录，必要时通过原业务管理入口预览差异并同步，不轮换凭据或修改共享 endpoint 绕过缓存。Trace 当前等待取真实 Run 状态，历史中断、唤醒与回流保留事件证据。短命令和冷启动真实异步通过，只证明传输与回流，不证明完整候选、取消或评分质量。

## 2026-10-22 性能对照必须区分物理对象与代码版本

探针、原始失败、采样顺序修正和后续测量状态，沿同一验收记录及本轮 `.tmp/sse-progress-review` 证据核对；不在知识库保存临时延迟数字或通过状态。

**Why:** 同一代码下两个不同 Work 的延迟比例，不能归因为分支相对 main 的开销；先排序再切批会破坏真实批次。并行编译、运行任务以及不均衡的执行顺序也会污染对照。

**How to apply:** 保留每次原始失败；分别对照 main/current 与同一物理对象，固定代码和探针哈希，预编译后在无编译竞争时测量。采样按采集顺序分批，分位数排序使用副本；平衡条件顺序及前序影响。源码变化后重新冻结，不能复用旧二进制证明最终改动性能；对象差异与代码差异分别报告。

## 2026-10-22 冻结资源编辑与运行包完整同步

真实技术编辑、确认、登记与尚未完成的执行边界，沿 Maxwell `output/evolve-unified-20261019/flexibility-acceptance-20261022.md` 查证。源码入口为 EVOLVE resourcecontent/source_runner、commands/resource_edit/runner_wire，以及 nextplay-a2a Skill 和 scripts/run.py；不保存临时资源身份、用量或发布状态。

**Why:** Work 的历史 executor/profile 和内层业务投影不等于当前资源授权；新增相等门禁会拒绝已经批准、合法可运行的 A2A 候选。模型回传整份原件既昂贵又易损坏字节。另一方面，Skill 说明可见不代表 Sandbox 已同步全部运行依赖，只复制脚本和环境文件会使 ZIP 中的 Python 模块不可导入。

**How to apply:** 复用已有冻结资产可见性、业务隔离、精确引用、哈希及当前活动 Runner 通道校验，不能凭旧画像增加顺序或配置相等要求。对实际可编辑的 UTF-8 prompt/skill_file 按窗口阅读、唯一匹配修改，由平台存储完整不可变原件并返回小型引用；只读库存不能覆盖已生效的同维度替换。扣额前可用元数据检查编码资源的严格下界，仍须保留完整信封上限；每次读取整份单资源不应称为存储 Range。Skill 的 scripts、assets/runtime.zip 和 runtime.env 必须来自同一包并保持目录关系；入口缺包给出可操作错误，用仅脚本的负例和完整包无 PYTHONPATH 的启动验证。完整复制后仍出现同类报错须继续取证，不能用已解释的首次缺包覆盖未知原因。原件成功、确认及候选登记仍不代表实际配置已应用或质量提升。

## 2026-10-22 模型条件字段与原件生产消费贯通

复现、修复和实际验收状态沿 Maxwell `output/evolve-unified-20261019/flexibility-acceptance-20261022.md` 查证；源码入口为 model/openaicompat/tool_schema、nextplay_runtime/evidence_bundle，以及原 evidence_pull/grading_evidence 消费者，不在本页固化动态调用数或发布结论。

**Why:** 将多动作工具的条件字段合并到生成用根对象后，仅保留必填说明，会让其它动作的可选字段看似处处可传，而原闭合执行契约仍会拒绝。原件写入成功、结构测试通过，也不代表原评分消费者能解析：展示压缩前若保存了错误层级，严格 receipt/status 校验会拦住真实结果。源配置的退役证明与候选的预期新增工具选择若混为一份清单，也会误拒合法变化。

**How to apply:** 只在模型副本保留每个闭合动作全部允许字段及条件，稳定输出且不改执行校验；不要用新的任意容量门槛将原本可投影工具回退到模型不支持的协议。使用真实生产者连接原严格消费者、原 Judge 导航，并保留篡改负例；原始信封先封存，展示结果随后压缩，不能靠放松消费者通过。源的完整退役证据与本次候选声明分开核对，实际配置须等于本次意图扣除仅被证明退役的源项，新增工具丢失或未声明变化仍拒绝。并行 Run 槽位、单 Run Trial 上限与执行器额度分别核验；多数排队阶段的单标签不能代表无人执行，页面应同时显示真实阶段计数。当前是否已真实提分仍沿验收原件核对。

## 2026-10-22 大输入接纳、执行期限与中断原件

完整复现与技术/真实验收分界沿 Maxwell `output/evolve-unified-20261019/flexibility-acceptance-20261022.md` 查证。源码入口为 EVOLVE A2A Registry、Native Runtime Task 投影，以及 nextplay-eval 的 CLI、event_archive、grading_evidence 和 archived_maxwell_events；当前发布与质量结论不保存在本页。

**Why:** 只缩短状态轮询仍会遗漏异步接纳响应对大输入的回显，响应丢失后也不能重派付费任务。调用方已经给出期限，但规范化或后台子进程若丢弃它，既可能提前中止合法长任务，也可能越过短期限。中断时的已观测事件尚未形成完成 Turn；只测试生产者封存成功，会漏掉原 Judge 对尾部槽位及 Run 集合的拒绝，或清理线程后永久丢失诊断。准备与确认间仅核对题数，也挡不住同题数换成员。

**How to apply:** 独立结果通道在接纳与轮询均使用已有零历史能力，通用 peer 保留原有历史语义；核对原输入、身份、问答和最终证据，不能把合成字节缩小推论成线上数据库 SLA。期限从已有原始请求取值，显式上限只能缩短，子进程重算绝对剩余时间；已过期不得发新执行，已有封存检查点仍须可恢复。失败轨迹不伪造成完成 Turn，原件成功持久化前不得清理，封存异常或容量超限保留恢复租约；生产者、消费者和实际 Judge 解析需一起测，保留原绑定、哈希、失败状态及公开协议。准备计划固定已解析选题修订并绑定摘要，旧未固定卡片明确要求重新准备；不靠读取最新版本或相同题数替代精确审阅。

## 2026-10-22 续期准入、进度事件与实际配置字节

本轮源码、首轮失败、主线整合、聚焦回归与真实执行边界见 Maxwell `output/evolve-unified-20261019/flexibility-acceptance-20261022.md`；暂时配置和业务原件不进入知识库。
