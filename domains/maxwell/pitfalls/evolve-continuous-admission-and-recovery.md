# 持续调优的准入、原子许可和恢复边界

**Why:** 单语句 statement_timeout 不能限制多语句事务的总耗时；只统计当前 Work 会漏掉候选独立验证和历史重评分；在 Run 写入前开放许可，可能在 Trial 图失败后留下仍可派发的 Search。旧 Worker 的领域版本与调度租约也是两种不同的竞态，单靠乐观版本无法撤销自动动作。

**How to apply:** 新模式用事务外来源／模型／对象写入和有界数据库准入，期限必须覆盖 Begin 前后的锁等待与全事务。根预算从服务端持久关系推导，未初始化不能按零放行；旧根先静止、封闭，再在锁外核对完整子链路，正式 Run／Trial 和固定计数同事务提交。新 Search 的外键指向实际首个基线 Run，等待基线时没有诊断；真实完成后才能规划。许可与该图同事务发布，提交不明按不可变回执恢复；重放核对原 Run 的人类许可指纹，不借 Search 当前可变许可覆盖旧请求。同一幂等键换范围或限额必须冲突。

停止后只允许有限的人工规划及已接纳执行的结果收敛；携带自动租约的写入必须再次验证当期 Search、generation、owner/token 和截止时间，不能借人工规划例外继续生成。跨目标版本保留根累计额度与最初截止时间，只释放未提交验收预留。初始化还须检查未确认远端取消，不能把本地 Run 终态等同远端已回收。

2026-10-19 复审已在隔离本机 PostgreSQL 验证事务总期限、旧验证／重评多层家族计数、首个 Search／Run／许可联合回滚、重放与停止隔离；浏览器技术夹具发现并修复通用表单 label 样式覆盖 Checkbox 的布局问题。技术夹具不证明真实候选已应用、评分或改善；公开执行编排、来源复现及完整真实验收仍需继续完成。

## JSONB、原件容量与进度读取

**Why:** 紧凑 JSON 的 UTF-8 长度不等于 PostgreSQL `jsonb::text` 字节数：分隔空格和科学计数法的十进制展开会增大检查值。单个合法冻结 Variant 也可能因外层元数据／转义超过原对象限额，多候选合装会进一步放大。只保留部分候选引用而不先记录完整生成清单，崩溃后可能把部分结果误认为完整一轮。历史逐次验收结果内联也会抵消轮次正文外置的收益。

**How to apply:** 在预算锁外按数据库表示做保守容量预检，并与真实 PostgreSQL 文本字节数对照；用最大字段、转义、引用数及下一次迁移的组合证明热状态空间，不能仅测试平均大小。大候选逐个可靠保存后再调用下一次生成；必要时使用有界元数据加独立原始正文，保持原字节、哈希和方法回执，不提高协议单对象上限。完整候选意图先落检查点，缺失原件时阻塞，禁止重放结果不明的付费调用或把部分结果发布为完整轮次。历史验收结果沿有界原件引用读取，当前状态只保留最新小投影；提交未明、GC 协同仍须单独验证。

进度 SSE 应批量统计整份 Run 的 Trial／实际已评分进度，并在分页前使用正式目录的完整权限与来源过滤；不能逐 Run 读取第一页 Trial 后声称整体进度。租约续期不进入安全摘要变化比较，避免把后台心跳放大为界面刷新。隔离本机数据库实验、模拟接口浏览器操作和真实目标／Judge／候选效果是不同层级的证据，沿下方执行记录查看当前覆盖与未完成范围。

## 2026-10-20 原件复用、决策收尾与真实 UI 生命周期

**Why:** CAS命中相同旧字节并不自动刷新保留时间；回收器的全局扫描锁没有隔离之后的写入。控制热态又独立于Candidate和Work，人工正式决策若只更新旧两者，会让自动许可与页面阶段留在旧状态。React StrictMode重放effect清理时，永久disposed的可复用Store也可能令开发页面按钮失效，未启用StrictMode的模拟页看不出来。

**How to apply:** 内容复用与最终删除使用同一跨节点按hash协调，并在复用成功返回前刷新保留时间，继续保留最短年龄保护；锁池与业务查询池分离，检查嵌套持锁和连接容量，不把它扩大为全局GC写入栅栏。参与者协议不一致的滚动／回退窗口不能据此宣称安全，上传前pending、提交未知与重启仍分别验证。正式决策沿原Work→Candidate事务收拢调度终态，失败一起回滚，旧Worker失效且累计额度与原期限保留；这不代替真实质量Gate或业务侧应用回执。

页面按实测Run的冻结Objective读取评估依据，不沿Work初始目标或最新草稿猜测；缓存身份包含精确Artifact ID与hash。沿产品真正的StrictMode入口验证mount/cleanup、旧请求晚回与未知提交恢复，不以单纯Story/模拟页按钮可点击替代。性能实验需在同一后台写负载下交替读新旧对象，保留未达标样本，并独立核对历史列、TOAST、buffers和WAL；数值与当前交付状态查执行记录，不固化在知识页。

## 2026-10-20 来源消息、目标消费与完整采纳证明

**Why:** 目标只参与评分判断，不代表生成候选的模型已经收到该目标；材料来自“当前知识槽”也不能证明与旧轮次相同。单次请求的来源准备失败，只能说明本次没有投递，不能覆盖此前同操作的未知接纳。只检查一份比较报告和调度终态，也可能漏掉人工确认的第二轮独立验证。

**How to apply:** 候选生成按基线 Run 的精确目标及已确认资料引用取数，材料元数据批量读取、正文在锁外有界读取，超限需引用原件的结构化摘要而不是静默截断；不要把原件写入热状态或随心跳读取。消息重试保留原操作、正文、来源水位与队列语义；公开持久事件与这些身份一致时可直接核对接纳，无需再次读取原来源，也不能让迟到响应恢复旧输入或解锁新的发送。跨路由的派发状态须在模块 Store 中协调，技术夹具包含真实 StrictMode。

持续采纳应在人工入口重算全部已确认的独立配对、冻结指标策略、先前通过题与运行约束；事务外完成原件/比较检查，短提交事务核对同一 Search 版本、调度代数/修订和选中候选，避免旧决定跨越新目标或新增证据。签发内部比较证明不等于已完成业务验证，正向真实候选、双轮全新十题、用户采纳、CI 与部署必须分别取证。

隔离验收先查实际 dev 部署与配置，本地 API 和唯一 Worker 使用同代码/配置/scope/队列；私网依赖不可达不应扩大共享环境权限或消费 dev 队列。必要凭据和隐藏验收原件的本地复制是不同授权范围，自动审批拒绝时不更换导出方式绕过。临时原件、真实回执及派生敏感夹具保留在受限忽略目录，不提交 PR。环境连接、临时文件清理、授权回执及尚未通过的合并 Gate 沿[整合执行记录](/Users/leslie/Downloads/sandai-code/maxwell-ai/output/evolve-unified-20261019/progress.md)核对，本页不宣称已交付。

## 2026-10-20 付费候选原件与权限落库核对

**Why:** 只在 CAS 写完后登记恢复指针，会在登记失败时失去定位；大正文再包进 JSON 会因转义超过合法对象上限。已批准扩权也不代表管理接口已写入，执行器健康与预设读取成功更不证明 Prompt／Skill 已可读取。

**How to apply:** 在付费调用前保存精确动作并用同根短事务预留合法原件的最坏空间；已知结果先落小 manifest 与原始正文的两个 Hash，再在事务外写 CAS，按同一动作结算实际接纳字节并释放未用预留。结果不明不重放，部分对象缺失不冒充已恢复，GC 同时保护两份 Hash；停止、过期或撤权后仅允许完成既有预留下的有限留存，不恢复派发。用真实隔离 PostgreSQL/CAS 验证额度不足、未知提交、部分 Put、重启及最大合法原件，不能从技术测试推断候选有效提升。

权限问题先对齐业务、Key ID、真实请求 credential_id、只读权限清单和更新时间；授权、管理接口回执与独立读回分开记录。不输出密钥，不用替代凭据或切换身份绕过服务端拒绝。具体接口、失败 trace、临时容量、测试结果、真实对话暴露的问题及未完成项沿[三项整合执行记录](/Users/leslie/Downloads/sandai-code/maxwell-ai/output/evolve-unified-20261019/progress.md)核对，不把本页当 dev 已扩权或已发布的证明。


## 2026-10-20 结果提交回包丢失与原件额度交接复审

**Why:** 数据库已提交恢复指针但客户端收到错误，与事务没有提交是不同结果；若调用方立即退出、尚未写 CAS，即使持久化了精确 Hash 也不能还原已知正文。临时留存与正式注册若共用逻辑 ArtifactBytes 累计，交接时再次扣费，会让本可容纳的合法候选无法登记。此前“双 Hash + 预留”的说明只覆盖一部分边界，不能据此宣称未知提交与额度交接已经安全。

**How to apply:** 在同一动作身份下有限读回或幂等核对提交结果，核对两份 Hash、长度和意图后继续保存同一份已知响应；结果不明保持阻塞，不能再调用模型。临时容量预留与正式逻辑注册额度应有独立语义，同动作完成时原子交接，只扣一次正式逻辑额度；不能靠提高预算修复。对象 I/O 保持在预算锁外，不引入持锁历史扫描。验证覆盖提交成功但回包丢失、未提交、读回不可用、部分 Put、紧预算最大合法正文、重复回执和重启恢复，确认不新增模型调用或 Run/Trial。
